# Runtime and provider configuration

The code phase does not require entering these secrets or connecting production services. Configure them later, securely in Cloudflare environment settings; use `.dev.vars` for private local Workers bindings. No private credentials were present in this cloud machine. Existing public Supabase configuration was reused. Never paste secrets into chat, Git, a PR, or a `VITE_` variable.

The development server, production compilation and isolated tests run without provider secrets. Feature-specific operations fail closed until configured. Proxy placeholder bindings can authenticate supported HTTPS requests, but cannot replace raw local HMAC/JWT signing keys or S3 credentials passed to another provider. Those belong in real Worker secret bindings.

## Provider setup in the later integration phase

1. Supabase: enable email confirmation; set Site URL and allowed auth/reset redirects to the independent origin and approved local/staging origins. Bootstrap admins using a verified user UUID through trusted database administration. Signing up with the founder's email no longer grants admin rights. Review existing `user_roles` grants inherited from historical migration 0005.
2. Apply/reconcile the ordered SQL against a staging copy first. Verify private credential storage, bucket MIME/size restrictions, RLS and role grants before enabling real uploads. Credential evidence is PDF/JPEG/PNG/WebP, max 10 MB or the existing stricter bucket limit, in the uploader's UUID folder; submitted evidence cannot be replaced or deleted.
3. Bunny: configure the correct library, TUS upload access, **embed token authentication**, token key and approved embed/referrer origins. Pending uploads and raw recordings must stay private at the provider too; database RLS alone cannot protect a library with public unauthenticated embeds. Configure appropriate retention for abandoned uploads.
4. Stripe: use test keys initially. Enable Connect Express with transfers. Register `/api/public/webhooks/stripe` for checkout completion/async success, charge refunds, and dispute creation/closure. Use the API version supported by the locked Stripe SDK. Processing fees must be available from the charge balance transaction; settlement retries rather than estimating a fee. Supply a real HTTPS `APP_ORIGIN`; no old application redirect is used.
5. LiveKit: configure `/api/public/webhooks/livekit` for signed room participant and Egress events. Enable Egress and bucket-scoped R2 S3 output. Private sessions are not recorded automatically. Community-class recording policy defaults on; a trainer can opt out using the persisted class policy before hosting. The audience sees a recording notice.
6. Cloudflare: create the private `tryumph-recordings` R2 bucket (or update its reviewed name), the `tryumph-recording-imports` queue, and `tryumph-recording-failures` dead-letter queue. Bind them according to `wrangler.jsonc`. The queue streams media, creates a pending video and preserves approval on retry. A five-minute scheduled handler retries refund/room-shutdown work and closes expired/no-show classes. Queue and R2 names are configuration, not proof remote resources were created. Inspect dead letters and retry imports from Studio.
7. Sponsors: no external ad provider was selected or invented. The first-party workflow uses actual admin-approved campaign creatives. Measurements are authenticated, require visible loaded media, have a minimum receipt age and deduplicate a member/video/break/day. They **never** create earnings. A trusted billing service must sign only independently recognized, paid sponsor revenue. The internal adapter contract is below; agreement, invoice verification and provider approval remain external prerequisites.

## Recognized sponsor settlement adapter

`POST /api/public/webhooks/ads` receives JSON with `network`, stable `networkEventId`, approved `videoId`, exact trainer-marked `breakSecond`, integer `grossCents`, integer `feeCents` and a millisecond `timestamp`. `x-tryumph-signature` is the lowercase hex HMAC-SHA256 of the exact request body using the private settlement key. Events must be within five minutes. The unique network/event key makes retries idempotent. Only the trusted billing integration holds this key; browsers never do. There is no payment claim from an impression counter or test creative. Do not enable payable settlement until the actual sponsor billing authority and recognized-revenue reconciliation are approved.

## Financial behavior to review in test mode

- Paid group classes: $5. Private sessions: trainer-defined valid USD rates. On-demand and Trybe membership: free. No mandatory recurring subscriptions for members or trainers.
- Shares: private trainer 90%; group live and recognized ads 50%. Apply actual processing fees first; hosting/infrastructure costs are excluded. Round trainer cents down; the platform receives the remainder.
- Wallet credits are Stripe-funded units, with an immutable redemption for each use. A cancelled class returns its token once. Refunds revoke unspent units before spent units; a fractional token refund queues the remaining refund needed to complete that $5 unit. Review this full-unit refund policy in Stripe test mode before launch.
- An ordinary cancellation before a private session starts requests a full refund. A cancelled class requests refunds for paid registrants. Past private sessions require support review. Duplicate class payments and paid reservations that cannot be fulfilled queue refunds rather than granting a second entitlement.
- Payouts are explicitly run by an admin, with persisted leases and stable per-operation Stripe idempotency keys. Failed transfers/reversals remain recoverable; do not clear operation state manually. Disputes suspend access and payable shares; a won dispute restores entitlements and creates an auditable recovery adjustment when money was already reversed. Live verification of funds availability, chargebacks, partial refunds and recovery is still mandatory.
- Existing pre-migration profile wallet balances, paid bookings and older ledger entries must be reconciled against Stripe; editable profile JSON is never accepted as paid authority. Preserve these records while investigating. Do not treat a missing verified lot/access row as permission to mint an entitlement.
