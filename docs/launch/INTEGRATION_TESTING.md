# Later integration test sequence

Use a staging Supabase copy, a separate Worker origin, Stripe **test mode**, test LiveKit/R2 resources, and actual provider test uploads. None of the steps below were represented as verified production behavior during coding. Preserve server logs privately and record provider event IDs without logging keys. Do not alter production DNS, apply production SQL or process real payments as part of this checklist without separate approval.

1. **Admin:** bootstrap a confirmed test user's UUID through trusted administration. Verify members/trainers cannot insert `user_roles`, see the admin UI as authorized, review their own records, or call privileged server functions. A signup using the historical owner email must not automatically become admin.
2. **Trainer signup:** register a real test trainer, verify email, sign in/out, refresh, recover/reset the password, and edit their photo, biography, specialties, HTTPS links and price. Reload to prove persistence. Confirm callbacks stay on the independent staging origin.
3. **Certification upload:** submit PDF/JPEG/PNG/WebP evidence in the trainer's UUID folder. Reject cross-user folders, unsupported MIME types, oversized files, overwrites and deletion after submission. Anonymous/non-owner HTTP reads must fail. Renewals create a new pending row and retain previous decisions.
4. **CPR/AED verification:** use an independent admin to verify current CPR **and** AED proof (combined or separate). Test expiry, missing verifier, revocation and the 30-day warning. Confirm badges and server eligibility follow authoritative records; changing profile JSON must not help.
5. **Video upload:** upload a real short Bunny video; exercise progress, failure and retry behavior. Save title/description, duration, required/optional gear, style, goals, Spotify playlist and valid water breaks. A different trainer must not attach that media as their own.
6. **Video approval:** preview privately as owner/admin. An ordinary member cannot preview pending/rejected media or obtain its signed playback URL. Approve/reject with notes. Verify editing returns approved content to pending and invalidates public discovery. Provider embed authentication must also reject unsigned URLs.
7. **Five-video rule:** five pending uploads fail scheduling and hosting. Five approved uploads plus verified current CPR/AED pass. Expire/revoke a credential after scheduling and ensure new room tokens are denied.
8. **Directory:** GET `/api/public/trainers` with the real schema and service binding. Confirm actual eligible trainer records, optional fields, photos/links and prices; no credential paths, verification documents, arbitrary profile JSON, demo accounts or sensitive diagnostics.
9. **Discovery:** verify saved preference chips and Edit controls across sessions. Test no equipment, optional gear, goal/style differences, pregnancy/postpartum and explicit safety tags. Best/Close/Explore stay distinct; all exclude unapproved and paused launch content. Watch later/history and persistent programs use actual approved videos.
10. **Trybes:** join/leave for free. Test a leader's public and private posts, member-private posts, public discovery, joined feed and individual Trybe scope. Non-members cannot read private posts, comment/react, hide/pin, or modify another group. Official introductory prompts are attributed to Tryumph Gym.
11. **Storefront:** create/edit/publish/unpublish/delete a listing and upload a valid image. A second trainer cannot change it through direct REST writes. Open external/affiliate purchase links and confirm no Tryumph checkout or revenue cut is added.
12. **Programs:** create a program, edit its description, add/remove/reorder approved owned workouts, then reload on another session. Reject duplicate video IDs and another trainer's videos. Pending/rejected videos never become publicly visible through programs.
13. **Water-break sponsors:** add a genuinely authorized campaign as admin. No-break videos remain ad-free. Invalid markers and seeking never insert ads mid-set. A failed creative should leave the workout usable. Loaded visible creative produces at most one measurement per member/video/break/day, including refresh/replay. Measurement alone creates no earnings. Exercise a legitimate signed recognized-revenue event twice and verify one 50/50 after-fee allocation; invalid signatures/timestamps must fail.
14. **Class scheduling:** schedule with eligibility, edit future details/recording policy, inspect real registrations, block conflicting private reservations, and cancel. Confirm $5 drop-in pricing and clear status. A no-show scheduled class should cancel/refund during maintenance; an expired started class should end and queue room shutdown.
15. **Paid checkout:** pay $5 in Stripe test mode, wait for a verified event, then confirm exactly one grant and ledger earning with the actual settled fee. Test unpaid/failed checkout, async success, duplicate events and two payments for the same class. Unfulfillable paid reservations must queue refunds. Exercise funded wallet use, token returns, partial/full lot refunds and rebooking separately.
16. **Room permissions:** inspect actual verified LiveKit tokens. The trainer can publish; ordinary class attendees cannot broadcast/administer/record. A private paid participant can publish camera/microphone without room administration or screen sharing. Wrong identity, room, booking status or time must fail. Confirm host controls initialize from server-authorized roles after hydration.
17. **Recording:** opt into a community class recording, stop/end/cancel it and verify Egress termination. Accept only signed matching completion events with valid completed files. Verify a private R2 object, queue import to Bunny, one stable pending video on retry, no duplicate public record, and admin approval before discovery. Exercise partial/failed recordings, import lease retry, dead letters and Studio retry. Private sessions must not start recording automatically.
18. **Private booking:** use a legitimate trainer's current stored price, an available Central-time slot and real test checkout. Simultaneous attempts must not double-book. Verify paid participant access, future cancellation/refund and release of the calendar slot. Trainer/member account views must show authoritative paid/refunded/cancelled state.
19. **Refunds/payouts/disputes:** replay checkout/refund events. Refund before, during and after a transfer; repeat a reversal after a simulated save failure. Verify persisted operation keys and cumulative targets, available funds handling, Connect status changes, chargeback loss/win and recovery adjustments. A blocked reversal must stay visible/retryable rather than appearing paid. Reconcile wallet units and cent allocation. Audit legacy profile-only purchases against Stripe before enabling those entitlements.
20. **Domain readiness:** only after review, migration, configuration and all test-mode flows pass, prepare an explicitly approved switch to `tryumphgym.com`. Inventory and preserve Google Workspace MX, SPF, DKIM and DMARC records and unrelated DNS. Configure independent auth, checkout, media origins and webhooks before switching. Keep a rollback plan; this task did not migrate the domain or deploy/merge code.

Optional push delivery also needs the account's `VITE_VAPID_PUBLIC_KEY`, matching private signing configuration, and an authorized scheduler for the existing protected push endpoint. In-app reminders now use persisted class timestamps; push delivery is not established merely by browser notification permission.
