## Important behavior changes

- Browser profile saves no longer write wallet, bookings or paid access. Forged balances, approvals and role grants fail at the database boundary.
- Credential renewals preserve old evidence/decisions. Unknown permissive storage/video policies cannot override the added restrictive guards.
- Trainer approval does not come from cached profile JSON. Five uploaded/pending videos never unlock a live room.
- Private booking is based on the trainer's actual configured rate and a held slot. Paid room permissions come from server records, not caller-provided trainer/room labels.
- Wallet credits are individual paid units. Refunds/cancellations maintain immutable redemption and earning references; a second payment for the same class is queued for refund.
- Transfer and reversal operations persist their amount and Stripe key before contacting the provider, so a process/save failure does not justify sending another payment with a new key.
- Advertiser measurements do not create earnings. Only the separate trusted recognized-revenue adapter may settle actual sponsor revenue.
- Recorded classes enter pending review. Queue retries cannot reset an already imported video's approval or create a second public record.
